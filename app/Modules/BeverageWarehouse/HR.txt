Extend the existing 360 Management ERP application with a comprehensive Human Resources, Workforce Management, Attendance, Payroll and Employee Accountability module.

This is NOT a new application.

Do not redesign, replace, remove, rename, or break any existing functionality, database relationship, workflow, API, permission, page, POS logic, inventory logic, warehouse operation, reporting function, or user experience unless specifically required for integration.

The new module must be developed as a backward-compatible extension of the existing system.

Before implementation, study the existing architecture, database structure, authentication system, roles, POS, inventory, warehouse, finance, reporting and existing employee/user records. Reuse existing components wherever appropriate.

1. Employee Master Profile

Create a central Employee Master Profile that becomes the single source of truth for every employee in the ERP.

Each employee should have a unique Employee ID, automatically generated by the system.

The profile should support information such as:

Possible employee statuses should include:

Applicant → Onboarding → Active → Suspended → On Leave → Resigned → Terminated → Inactive.

Do not permanently delete historical employee records where those employees have transactions attached to them.

2. Recruitment and Staff Onboarding

Create a proper employee onboarding workflow.

HR/admin should be able to:

Create applicant → enter employment information → upload documents → complete KYC → assign department → assign job role → assign permissions → assign location → enter payroll information → approve employee → activate employee.

Allow employee documents such as:

3. Staff KYC and Identity Verification

Add employee KYC functionality suitable for Nigerian operations.

Support:

NIN
BVN
Phone verification
Bank account verification
ID documents
Address information

Where APIs are available, integrate with approved/licensed Nigerian verification providers.

The architecture must not permanently depend on one provider. Create an abstraction/integration layer so the verification provider can be changed later.

Possible verification statuses:

Not Submitted / Pending / Verified / Failed / Requires Review

Store verification references and timestamps, but do not expose sensitive BVN/NIN information unnecessarily.

Mask sensitive numbers on normal screens.

Example:

**BVN: *****4821

Access to sensitive KYC information must be permission-controlled and logged.

5. Workplace Attendance System

The organisation does not operate shifts.

Do not design the attendance system around shift schedules.

Attendance should operate using:

Clock In → Working → Clock Out

HR/admin should configure normal workplace attendance rules.

For example:

Opening time: 8:00 AM

Grace period: 15 minutes

Employee clocks in:

7:55 AM → On Time

8:10 AM → On Time/Grace Period

8:35 AM → Late

No clock-in → Absent

Allow management to configure these rules from settings.

11. Payroll Workflow

Payroll should follow an approval process such as:

Draft → Calculated → Reviewed → Approved → Payment Processing → Paid → Closed

Example:

HR prepares payroll.

Accountant reviews payroll.

Manager approves payroll.

Authorized finance personnel process payment.

After payroll closes, changes should require authorized reopening.

Create an Employee Accountability / Damage Register.

If company property, inventory, stock, equipment, vehicle, POS device or other asset is damaged or lost, the incident can be assigned to an employee.

Do not deduct money simply because an incident was reported.

The liability should first be approved by an authorized manager.

13. Payroll Deduction Integration

Approved employee liabilities should automatically become payroll deduction entries.

Allow options such as:

Deduct once

or

Installment deduction

Example:

Damage liability: ₦60,000

Deduction period: 3 months

Payroll deduction:

Month 1 — ₦20,000
Month 2 — ₦20,000
Month 3 — ₦20,000

The balance should update automatically.

14. POS Employee Integration

The same Employee Master Profile must integrate with the existing POS.

Do not maintain separate POS staff records.

An employee authorized for POS should sign into the POS using their employee identity.

The system should automatically recognize their role and permissions.

Example:

Create sale
Receive payment
Print receipt

But may not necessarily:

Change product prices
Delete transactions
Void completed sales
Approve refund
Give large discounts

Those actions require specific permissions.

37. Backward Compatibility — Critical Requirement

This is the most important implementation rule.

DO NOT BREAK THE EXISTING 360 MANAGEMENT ERP.

Before modifying any existing table, API, middleware, permission, authentication mechanism or business logic:

Identify where it is currently used.
Determine the impact of the change.
Maintain existing behavior.
Introduce migrations safely.
Test existing modules after implementation.

Existing:

POS

Inventory

Warehouse

Procurement

Sales

Finance

Reporting

Authentication

and all other working modules must continue functioning.

38. Implementation Approach

Do not attempt to build everything as one uncontrolled update.

Implement in controlled stages.

Recommended sequence:

Phase 1: Employee Master Profile + Roles + Permissions

Phase 2: Recruitment + KYC + Documents

Phase 3: Attendance + Attendance Terminal

Phase 4: Payroll + Payslip + Deductions

Phase 5: Damage & Employee Accountability

Phase 6: POS + Cashier Integration

Phase 7: Warehouse + Driver + Operational Accountability

Phase 8: Performance + Discipline + Reporting

Phase 9: Banking, biometric and other external integrations

After each phase, test the existing ERP before proceeding.

Final Developer Objective

The completed architecture should make the Employee Master Profile the identity layer for the entire 360 Management ERP.

One staff member should have one identity throughout the system.

That same employee identity should follow them through:

Hiring → KYC → Role Assignment → Clock In → Attendance → POS → Warehouse → Delivery → Damage Accountability → Payroll → Payslip → Performance → Audit Trail.

Management should ultimately be able to answer:

Who is this employee?

Has the employee been verified?

What is the employee authorized to do?

Did the employee come to work today?

What transactions did the employee perform?

What stock or assets were entrusted to the employee?

Were there shortages or damages?

What deductions have been approved?

How much should the employee receive this month?

Has the employee been paid?

Who approved each important action?

All of this must operate inside the existing 360 Management ERP, using the existing platform as the foundation rather than creating a separate HR application.
